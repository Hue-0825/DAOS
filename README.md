# DAOS — Distributed Autonomous Operation System

> 중앙이 멈춰도, 현장은 안전한 범위에서 스스로 운영을 이어간다.

국립창원대학교 2026 스마트물류 **문제해결 경진대회** 팀 프로젝트.

## 목표
중앙 서버 장애 시 **사전에 승인·저장된 데이터**로 배송기사, 물류 로봇, 물류센터가 제한적으로 업무를 지속하고, 복구 후 실제 물품 위치와 작업 이력을 검증하여 **중복·충돌 작업을 방지**하는 범용 분산형 자율운영 시스템을 개발한다.

## 주요 서비스
| 서비스 | 사용자 | 장애 시 핵심 동작 |
|---|---|---|
| DAOS Driver | 배송기사 | 향후 2~3일 중 확정된 작업 데이터 오프라인 조회·처리, 복구 후 동기화 |
| DAOS Robot | AMR/AGV 관제 담당자 | 작업 의존성과 공유 자원 점유권 분석, 안전한 작업만 제한적으로 분산 실행 |
| DAOS Factory | 물류센터 운영자 | 입출고 작업 지속 여부 판단, 재고 및 실제 물품 위치 검증 |
| DAOS Core | 공통 엔진 | 장애 감지·전환, 작업 이벤트 기록, 권한·데이터 유효성 검증, 복구 동기화 |

## 핵심 설계 원칙
1. **안전 우선:** 데이터가 불확실하거나 작업 충돌 위험이 있으면 자동 실행하지 않는다.
2. **2~3일치 백업 ≠ 72시간 무조건 운영:** 앞으로 확정된 주문/작업만 사전 저장한다. 새 주문, 변경 배송지 등은 제한·재확인한다.
3. **중복 금지:** 작업별 고유 ID, 상태 전이, 멱등성 검증을 적용한다.
4. **분산 독립성:** 백업 데이터/비상 제어가 중앙 서버 장애에 함께 영향을 받지 않도록 설계한다.
5. **복구 검증:** 서버 복구 직후 무조건 재전환하지 않고, 작업 로그·물품 위치·재고를 대조한다.
6. **규격 준수:** VDA 5050은 통신 인터페이스이며 안전 인증이나 로봇 전체 제어를 대신하지 않는다. 초기 데모는 가상 로봇으로 검증한다.

## 계획된 저장소 구조
```text
DAOS/
├── apps/
│   ├── driver-app/            # 배송기사용 오프라인 앱(PWA)
│   ├── robot-web/             # 로봇 비상 관제 시뮬레이터
│   └── factory-web/           # 물류센터 비상 운영 대시보드
├── services/
│   ├── main-server/           # 정상 운영 시뮬레이션
│   ├── backup-engine/         # 장애 감지/비상 운영
│   └── sync-service/          # 복구/충돌 검증
├── packages/shared/           # 이벤트·작업·위치 모델
├── simulations/               # 장애 재현 및 실험
├── tests/                     # 자동 검증
└── docs/                      # 설계, 데이터, 실험 계획
```

## 개발 순서
1. 프로젝트 구조·공통 데이터 모델·로컬 실행 환경
2. 중앙 서버, 백업 엔진, 장애 감지·전환 시뮬레이션
3. DAOS Driver: 확정 작업 캐시·오프라인 기록·복구 동기화
4. DAOS Robot: 작업 의존성 그래프·공유 자원 점유권·비상 관제
5. DAOS Factory: 입출고/실물 위치 대조 및 충돌 조치
6. 통합 실험: 중단 시간, 작업 지속률, 중복 처리율, 복구 정합성

## 경진대회 검증 KPI
- 장애 감지 및 비상 모드 전환 시간
- 장애 중 **안전하게** 완료된 작업 비율
- 중복 처리 및 작업 충돌 발생 건수
- 복구 후 작업 기록·실제 물품 위치 일치율
- 복구·동기화 완료 시간
