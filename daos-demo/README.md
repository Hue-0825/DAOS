# DAOS 물류 장애 대응 시연

쇼핑몰에서 주문을 받고 메인 서버가 시·도 허브로 분류합니다. 허브에서 배차를 확정하면 기사 앱이 작업표를 저장합니다. 연결을 끊으면 DAOS 모드에서 저장된 작업을 계속할 수 있고, 복구 후 완료 기록을 서버로 보냅니다.

| 구성 | 시연 주소 | 소스 |
|---|---|---|
| 쇼핑몰 웹 · `daos.store` | https://daos-shop-demo.ryker6365.chatgpt.site/ | `shop/` |
| 메인 서버 주문 원장 · `daos.main` | https://daos-dispatch-demo.ryker6365.chatgpt.site/central/ | `worker.mjs`, `central/`, `drizzle/` |
| 시·도 허브 · `daos.hub` | https://daos-hub-demo.ryker6365.chatgpt.site/ | `hub/` |
| 기사 앱 | Android APK 및 iOS Xcode 프로젝트 | `mobile/`, `driver/` |
| 물류센터 로봇 관제실 | https://daos-logistics.ryker6365.chatgpt.site/robot/ | `public-demo/robot/` |

시연용 이름 옆에는 현재 접속 가능한 배포 주소를 적었습니다.

## 시연 순서

1. 쇼핑몰에서 지도에 등록된 배송지를 선택해 주문하거나 메인 서버에 준비된 시연 주문을 사용합니다. 신규 주문은 11월 14일부터 하루 100건씩 접수 순서대로 배정됩니다.
2. 허브와 기사 앱에서 같은 시·도를 선택합니다. 2026년 11월 9일·10일·11일 주문을 날짜와 권역별로 배차할 수 있습니다. 배송지는 배차 카드에서 확인합니다. 허브 지도에는 배경만 표시됩니다.
3. 배차 확정 후 기사 앱의 작업표가 저장되고 허브에 백업 완료가 표시되면, 메인 관제센터에서 기사 작업 서버 연결을 끊습니다. 시연 시간은 이 상태에서도 계속 공유됩니다.
4. DAOS 모드에서 작업하고 서버를 복구해 미동기화 기록이 전송되는 것을 확인합니다.
5. 같은 날을 다시 시연하려면 서버를 복구한 상태에서 허브의 **배차 리셋**를 누릅니다. 선택한 시·도와 배송일의 시연 배차와 기록을 초기화하고, 주문을 배차 대기로 돌립니다. 리셋 이전 기기 기록은 재배차 후 수신 대상에서 제외됩니다.
6. 전체 시연을 처음부터 시작하려면 메인 서버에서 **전체 시연 리셋**을 누릅니다. 9–11일 기본 주문 300건을 배차 대기로 복원하고, 12–13일 200건을 전송 대기로 되돌립니다. 추가 접수 주문은 별도 보관합니다. 기사 앱은 서버에 다시 연결되면 작업표와 시연 상태를 초기화합니다.

## 로봇 관제실

메인 관제센터의 운영 웹 메뉴에서 별도 로봇 관제실을 열고, 같은 계정으로 접속 권한을 확인한 다음 시·도를 선택합니다. 오늘과 다음날의 허브 전송 주문을 메인 서버에서 읽으며, 현재 배송일과 열린 시간대의 주문만 작업에 사용합니다. 하차·운반·분류·출차 배정·상차에 로봇 20대가 참여합니다. 허브에서 배차를 확정한 주문만 출차 배정 이후로 넘어갑니다. 연결이 끊기면 이 탭에 확보한 작업표를 쓰고, 복구 시 서버의 작업표를 다시 조회합니다. 로봇 진행 상태와 로컬 공정 기록은 탭 내 시연 상태이며 실제 배송 완료를 변경하지 않습니다.

## 로컬 실행

Node.js 24 이상이 필요합니다. 압축된 정적 리소스만 제공되는 체크아웃이면 먼저 `tar -xzf assets.tar.gz`를 실행한 뒤 `node split.mjs`로 네 프로세스를 실행합니다.

- 쇼핑몰 `http://127.0.0.1:8780/`
- 메인 서버 `http://127.0.0.1:8781/central/`
- 허브 `http://127.0.0.1:8782/`
- 기사 앱 미리보기 `http://127.0.0.1:8783/driver/`

초기 실행 시 11월 9–13일에 100건씩 생성됩니다. 12일과 13일 주문은 메인 서버에서 배송일을 선택한 뒤 **허브로 전송**을 눌러야 허브에 표시됩니다. 시연 날짜와 시간은 메인 서버의 **시간 설정**에서 바꾸면 스토어, 지역 허브, 기사 앱에 적용됩니다. 기사 앱은 9–11일을 포함한 허브 일정을 요약해 표시합니다. 운행일과 다음날의 확정 작업표를 저장하고 현재 구간 시작 시각부터 선택한 배송지 한 곳을 지도에 표시합니다. 하루 100건은 06:00–12:00에 34건, 12:00–18:00과 18:00–24:00에 각각 33건으로 배정됩니다. 지도 핀은 시연 시설의 위치이며, 실제 하역 출입구는 별도 확인이 필요합니다.

## 기사 앱 빌드

- **Android** — `JAVA_HOME`, `ANDROID_BUILD_TOOLS`, `ANDROID_PLATFORM_JAR`를 설정하고 `bash mobile/android/build.sh`를 실행합니다. APK는 시연용 키로 서명합니다. 업데이트 설치에는 동일 키를 사용하세요.
- **iPhone** — `bash mobile/ios/prepare.sh` 후 `mobile/ios/DAOSDriver.xcodeproj`를 Xcode에서 엽니다. Signing & Capabilities에서 본인 Team과 고유 Bundle ID를 설정해 기기에서 실행하거나 TestFlight로 배포합니다. 기기 설치용 파일에는 Apple 서명이 필요합니다.
- 두 앱은 지도와 작업 화면을 설치 파일에 포함합니다. 최초 서버 연결 시 앱 상단 **서버 로그인**을 누르고 배포 사이트에 접근할 수 있는 계정으로 로그인합니다.
- 비공개 웹 서비스 키·환경값, 주문 데이터와 앱 서명 키는 저장소에 포함하지 않습니다.
