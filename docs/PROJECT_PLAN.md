# DAOS 프로젝트 요구사항 및 개발 로드맵 v1.0

## 1. 팀 합의 사항
- 목표: 특정 제조사에 종속되지 않는 **중앙 서버 장애 대응 범용 백업·자율운영 시스템**.
- 핵심 아이디어: 장애 시 **로봇별 작업 의존성**과 **공유 자원 점유권**을 분석하여 충돌 위험이 낮고 승인된 작업만 분산 실행한다.
- 복구 시 **물품의 실제 위치와 작업 이력**을 비교해 중복 작업을 방지한다.
- 배송기사 앱은 **당일과 다음날 출고 예정인 확정 작업 데이터**를 미리 저장해 오프라인 운영을 지원한다.
- 로봇과 물류센터 운영은 웹 시뮬레이터/관제 화면으로 구현한다.

## 2. 장애 범위와 안전 조건
| 상황 | 목표 동작 | 제한 |
|---|---|---|
| 중앙 서버 장애, 로컬 네트워크 정상 | 백업 모드 자동 전환 | 확정되고 유효한 작업만 수행 |
| 기사 단말기 오프라인 | 저장된 배송 조회 및 이벤트 로컬 기록 | 주소 변경/미확정 작업 보류 |
| 로봇 FMS 장애 | 소형 비상 관제에서 작업 의존성·자원 점유 판단 | 공유 통로 점유 불명·안전 검증 불가 시 정지 |
| 중앙 서버 복구 | 이벤트 재생·멱등성 검증·물품 위치 대조 | 불일치는 수동 확인 대기 |
| 보안 침해 의심 | 자동 동기화 차단, 격리 상태 알림 | 오염된 데이터 무분별한 복제 금지 |

## 3. 공통 데이터 모델 (초안)
- Order: id, destination, status, confirmedAt, updatedAt
- Task: id, orderId, type, assignedTo, dependencies[], resourceIds[], status, version, approvedUntil
- Resource: id, type, occupiedBy, leaseUntil, version
- InventoryItem: id, sku, recordedLocation, observedLocation, lastScanAt
- WorkEvent: eventId, taskId, actorId, eventType, occurredAt, source, sequence
- ServerState: component, health, detectedAt, mode

모든 메시지에 고유 식별자를 부여하고, 장애 중 처리한 이벤트는 **추가 전용 로그**로 기록한다.

## 4. 최초 시연 시나리오
1. 중앙 서버 정상 작동, 확정 작업을 로컬로 사전 복제
2. 중앙 서버 강제 중단 (웹 상태 변화 확인)
3. 기사: 저장된 배송 작업 완료 → 로컬 로그 기록
4. 로봇: 공유 통로와 선행 작업 충돌 여부 확인 → 안전한 작업만 배정
5. 물류센터: 입출고 처리 및 물품 위치 스캔
6. 중앙 서버 재시작 → 백업 로그 동기화 → 실물 위치/중복 검증 후 정상 전환

## 5. 검증 계획
| KPI | 정의 | 비교 조건 |
|---|---|---|
| 작업 지속률 | 장애 중 안전하게 완료된 작업 / 장애 기간 처리 대상 | 백업 없음 vs 사전 백업 vs DAOS |
| 전환 지연 | 실제 장애 시각부터 백업 모드 활성화까지 | 동일 장애 주입 |
| 중복 작업률 | 중복 처리된 작업 수 / 전체 처리 작업 수 | 반복 요청/복구 재시도 |
| 위치 불일치 | 복구 후 불일치 물품 수 | 위치 스캔 및 로그 대조 |
| 복구 완료 시간 | 중앙 복귀부터 검증·정상 전환까지 | 같은 작업·장애 규모 |

**주의:** 공개된 실제 기업 사고는 문제 동기이며, 시뮬레이션 수치는 실제 현장 성과로 단정하지 않는다.

## 6. 단계별 개발 이슈
- Phase 1: 저장소 구조, 실행 문서, 데이터 계약, 테스트 환경
- Phase 2: 중앙 서버/백업 엔진, 상태 전환, 작업 로그
- Phase 3: Driver PWA 오프라인 저장/동기화
- Phase 4: Robot 웹 + 의존성 그래프 + 점유권/리스 시뮬레이션
- Phase 5: Factory 웹 + 실물 위치 대조 + 충돌 검증
- Phase 6: 통합 테스트, 실험 데이터, 발표 자료

## 7. 역할 분담 제안
- 담당 A: 공통 엔진/API/데이터베이스
- 담당 B: Driver 앱/오프라인 기능
- 담당 C: Robot 웹/안전한 스케줄링
- 담당 D: Factory 웹/테스트 및 시각화

인원과 역할은 실제 팀 상황에 맞춰 조정한다.

## 8. 추가 팀 제안 — 로봇의 단기 독립 운영과 사후 동기화 (2026-11-07)

### 팀에서 제안한 문제
- VDA/VDMA가 공동 추진한 **VDA 5050 통신 인터페이스**를 활용하는 중앙 관제 시스템(MCS/FMS)과 로봇 사이에 네트워크 장애가 발생할 수 있다.
- 중앙 관제 또는 메인 서버에서 더 이상 새 작업 정보를 받지 못하면 로봇 및 개별 설비의 운영이 중단될 수 있다.
- 통신 복구 후 장애 중 생성된 작업 내역이 중앙 DB에 반영되지 않으면 상태 불일치와 중복 작업 위험이 생긴다.

> 용어 메모: **VDMA는 협회 이름**이며 로봇 통신 표준 이름이 아니다. 통신 형식은 **VDA 5050**이라고 표기한다. 표준 메시지를 사용한다고 해서 통신 장애 중 자율 작업이나 안전성이 자동 보장되지는 않는다.

### 팀이 제안한 동작
1. 정상 운영 중 로봇/장비에 **단시간 작업 수행에 필요한 기존 작업 명령, 경로 정보, 운영 규칙**을 사전 저장한다.
2. 중앙 관제 시스템 및 메인 서버 연결이 끊기면 장애를 감지하고 비상 운영 모드로 전환한다.
3. 로봇이 사전 할당받은 작업 중 **작업 의존성·공유 자원 점유권·현재 안전 상태**가 확인된 것만 독립 실행한다.
4. 장애 중 로봇의 상태 변화, 수행 작업, 이동 결과, 오류 및 이벤트를 로컬 저장소에 기록한다.
5. 연결 복구 시 로컬 작업 이벤트를 중앙 관제로 전달하고, 중앙 DB에 반영하기 전 **고유 이벤트 ID·중복·작업 상태·실제 물품 위치**를 검증한다.
6. 중앙 시스템과 상태가 일치하는 것을 확인한 다음 정상 관제권을 복귀시킨다.

### 안전·구현 경계
- **단기 운영**과 배송기사의 **당일·다음날 작업 사본**은 서로 다른 범위다. 로봇 작업 권한과 공유 통로 점유 정보는 수일간 유효하다고 가정하지 않는다.
- 공유 공간 점유 상태를 확인할 수 없거나, 사전 승인된 경로를 벗어나거나, 다른 로봇과 충돌 가능성이 있으면 해당 작업을 보류한다.
- 로봇 자체 통신·센서·안전 기능이 고장 난 경우에는 비상 관제만으로 운행을 계속하도록 하지 않는다.
- 초기 시연은 **가상 로봇과 가상의 관제 메시지**로 검증하고, 실제 VDA 5050 규격 준수 여부는 별도 테스트로 입증한다.

### 시연·평가 항목
- 메인 MCS 연결 종료 → 가상 로봇의 비상 모드 전환
- 서로 독립적인 작업은 이어가고, 공유 통로 충돌 작업은 대기
- 로봇별 이벤트 로그 보존 및 중앙 복구 후 동기화
- 중복 작업 건수 / 안전한 작업 지속률 / 관제권 인계 시간 / 동기화 후 상태 일치율 측정

**본 절은 팀의 신규 요구사항이며 구현 및 검증 전 기획 단계이다.**

## 10. 대기업 적용 후보 — 쿠팡풀필먼트서비스 대구 FC (2026-11-08)

### 아이디어의 출발점과 공개 장애 사례

DAOS의 출발점은 **쿠팡 중앙 서비스 장애가 물류 현장의 스캔·분류·배송 처리까지 영향을 줄 수 있다는 문제**다. 공개 사례로 2026년 10월 9일 장애를 사용한다. 쿠팡 고객센터 공지를 인용한 보도에 따르면 서비스 업그레이드 과정에서 접속 오류가 발생해 약 2시간 반 뒤 해소됐다. 물류 현장의 상품 소분·스캔과 배송 시작·완료 처리에 차질이 있었다는 보도도 있다. 어떤 내부 서버가 장애를 일으켰는지, 대구 FC가 해당 장애의 영향을 받았는지, 물류 중단 시간과 손실액은 공개 자료에서 확인되지 않았다. [전자신문의 쿠팡 공지 인용 보도](https://www.etnews.com/20261009000022) · [뉴시스의 물류 현장 보도](https://nwww.newsis.com/view/NISX20261009_0003820074)

**적용 후보는 쿠팡풀필먼트서비스(CFS) 대구 풀필먼트센터의 분류 구역 한 곳**이다. 쿠팡은 대구 FC에서 무인 운반 로봇(AGV)과 소팅봇을 운영하고, 포장된 상품의 운송장 바코드를 읽어 배송지별로 분류한다고 공개했다. 이를 바탕으로 대회에서는 사전에 승인된 포장 완료 물량을 현장 스캐너와 가상 로봇으로 분류해 인계 대기 위치까지 보내는 시나리오를 만든다. 공개 자료가 확인해 주는 것은 자동화 환경이며, 실제 연동 규격·도입 의사·기존 비상 대응 범위는 현장 검증 사항이다. [쿠팡 대구 FC 공식 소개](https://news.coupang.com/archives/26330/) · [CFS 2026년 자동화 장비 공개](https://news.coupang.com/archives/64632/)

### 기존 DAOS를 적용하는 범위

- **정상 시** 한국시간 기준 당일과 다음날 **출고 예정**인 주문 중 확정·할당된 작업만 별도 장애 영역의 현장 장치에 저장한다. 작업·박스·운송장 식별자, 분류 목적지, 마감, 작업 버전과 실행 승인 만료 시각 등 현장에 필요한 필드를 포함한다. 주문 변경·취소는 정상 시 5분 간격 갱신을 목표로 하고, 자정 이후 첫 성공 갱신부터 새 날짜 범위를 반영한다.
- **자정 경계**에서는 마지막으로 성공한 갱신에 포함된 작업과 권한만 사용한다. 11월 8일 밤에 연결이 끊겼다면 8~9일 출고 예정분 중 이미 받은 유효 작업만 후보로 삼는다. 자정이 지나도 10일 작업을 자동으로 추가하거나 만료된 권한을 연장하지 않는다. 작업 캐시가 날짜 범위에서 빠져도 미확인 작업과 미전송 이력은 복구 대조를 위해 따로 보존한다. 날짜 범위는 사본에 들어갈 작업을 정하며, 비상 운행 가능 시간은 별도로 제한한다.
- **중앙 서버 장애 시** 첫 적용 구역은 기존 로봇 관제와 현장망이 살아 있는 한 구역이다. 마지막 성공 갱신의 최신성(전환 시점 기준 데모 목표 15분 이내)과 중앙 명령권 격리를 확인한 뒤 이미 승인된 운송장·박스 ID·분류 목적지 목록을 현장 단말에서 검증하고, 분류와 이송을 제한적으로 수행한다. 스캔과 임시 작업 기록은 사전에 승인된 현장 계정·장비로 처리한다. 중앙 서비스에 의존하는 로그인·바코드 검증이 현장에서도 가능해야 한다. 신규 주문·결제·운송장 재발급은 중앙 복구 이후 처리한다. 작업 데이터가 만료되거나 취소 여부·실물 위치·공유 통로 점유가 불확실하면 보류한다. 로봇과 브로커까지 단절된 경우에는 제작사가 검증한 안전 기능 아래 마지막 승인 노드 이내에서 안전하게 정지한다. 물리적 인계는 송장·분류·인계 절차까지 현장에서 유효한 경우에만 실적으로 센다. [VDA 5050 v3.0.0 §1·§4.1](https://www.vda.de/dam/jcr%3A09f03b91-13e2-4db3-bf30-4f221710071b/VDA5050-V3.0.0-2025-03.pdf)
- **복구 시** 현장 로그를 재전송하고 이벤트 ID와 작업 버전으로 중복 반영을 막는다. 실물 위치·수량·인계 결과를 대조하고 충돌 건을 격리한 후 정상 관제권을 인계한다.
- **도입 조건**으로 현장 권한과 주문 사본의 분리, 기존 WMS/FMS와의 연동 가능 여부, 로봇 제작사와 안전 담당자의 검증, 운영기술(OT) 보안 검토가 필요하다. 평가 기준선에는 후보 센터의 실제 이중화·재해복구·수작업 절차를 모두 포함한다. 실제 연동 전에 오프라인 스캔, 취소로부터 보호할 수 있는 작업 범위, 중앙·현장 동시 실행 방지, 유효기간, 실물 인계 절차를 확인한다.

### 대기업 도입비와 손익분기점

[중소기업 비교 연구](SME_RESILIENCE_STUDY.md)는 초기 조사 근거로 사용한다. 대기업 평가는 **기존 대응 대비 DAOS의 증분 비용과 편익**으로 별도 계산한다. 한 구역의 연동·검증·설치 초기비 3,000만원, 유지·점검·복구 훈련 연 600만원을 예시로 두면 3년 회수에 필요한 연간 추가 절감액은 **1,600만원**이다. 쿠팡 내부 견적이나 손실 실측을 확보하기 전의 시나리오다. 공개된 약 2시간 반의 접속 장애를 로봇 가동 가능 시간이나 물류 중단 시간으로 환산하지 않는다. 기존 이중화로 복구한 물량과 이후 정상 처리한 주문의 매출은 편익에 합산하지 않는다.

| 기존 대응 이후 남는 장애 중 DAOS 적용 가능 횟수 | 회당 추가로 피해야 할 평균 손실 |
| --- | ---: |
| 연 1회 | 1,600만원 |
| 연 2회 | 800만원 |
| 연 4회 | 400만원 |

예를 들어 연 4회에서 회당 추가 운송·초과근무·계약 배상 등 500만원을 실제로 피할 수 있다면 연 편익은 2,000만원이다. 3년 환산 증분 비용을 반영한 순편익은 연 400만원이며, 연 운영비를 뺀 현금성 절감액이 일정할 경우 단순 회수기간은 약 2.1년이다. 마감 직전에는 차량 한 대를 추가 투입해야 하는 등 비용이 비선형이므로 장애별 원장·운송 영수증·계약 조건으로 회피액을 확인한다.

### 당일·다음날 사본의 장애 손실 비교

한 분류 구역에서 집하 마감 직전에 중앙 서버가 끊기는 가상 사례다. 마감 대상 1,200박스 중 기존 이중화·수작업으로 600박스를 제시간에 인계한다고 가정한다. DAOS는 비상 실행 창 최대 60분 안에, 기존 대응과 겹치지 않는 유효 작업 300박스를 추가 인계한다. 지연 박스 1개당 평균 2,000원의 **추가 재분류·재처리 실비**만 적용하며, 새 주문 기회 손실·상품 매출·추가 차량비·보상비는 제외한다. 수치와 절감 효과는 검증할 가정이며 쿠팡의 실제 처리량, 요율 또는 손실이 아니다.

| 비교 방식 | 마감 전 인계 | 마감 지연 | 장애 1회 손실 |
| --- | ---: | ---: | ---: |
| 기존 이중화·수작업 대응 | 600박스 | 600박스 | 120만원 |
| 기존 대응 + DAOS 당일·다음날 사본 | 900박스 | 300박스 | 60만원 |
| 기존 대응 + DAOS 2~3일 작업 사본 | 900박스 | 300박스 | 60만원 |

이 사례의 마감 물량은 모두 당일·다음날 사본의 범위에 있고 실행 창과 자원 제약도 같다. 2~3일 사본에만 있는 작업이 그 집하 회차에서 처리되는 경우는 0건이므로 손실 차이는 0원이다. 자정 전후 및 장기 장애 시험에서는 추가 보관분의 실제 승인·인계 가능 여부를 별도로 검증한다. 이 비교는 현장용 작업 사본의 범위에 관한 것이며 재해복구 사본은 별도 정책을 적용한다.

| 연 4회 같은 유형의 장애 가정 | 기존 대응 | 당일·다음날 DAOS |
| --- | ---: | ---: |
| 연간 장애 손실 | 480만원 | 240만원 |
| 연간 증분 운영비 | 0원 | 600만원 |
| 운영비 + 잔여 손실 | 480만원 | 840만원 |
| 구축비 3년 환산분까지 포함 | 480만원 | 1,840만원 |

이 시나리오에서는 장애당 60만원, 연간 240만원을 절감한다. 기존 대응 대비 연간 비용은 초기비 제외 시 360만원, 3년 환산분 포함 시 1,360만원 증가한다. 연 4회에서 3년 내 회수하려면 회당 평균 400만원의 추가 절감이 필요하다. 마감 준수로 긴급 차량 비용이나 계약상 배상을 실제로 피한 사례가 있으면 증빙에 따라 사건별로 추가하고, 박스당 비용에 이미 포함된 항목은 다시 집계하지 않는다.

### 장애 시간별 적체와 물류센터 총비용

대상은 쿠팡 대구 풀필먼트센터의 **분류 구역 한 곳을 본뜬 가상 운영 구역**이다. 쿠팡의 연결 공시는 풀필먼트센터 운영·인력, 기술 인프라, 감가상각 등을 비용 항목으로 공개한다. 아래는 비용 구조를 참고한 가정이며 대구 센터나 구역의 실제 원가·생산성·장애 손실을 뜻하지 않는다. 실제 장애 보도의 약 150분은 시험 길이로만 사용한다. [Coupang 2025 Form 10-K](https://www.sec.gov/Archives/edgar/data/1834584/000183458426000024/cpng-20251231.htm) · [2026년 10월 접속 장애 보도](https://www.etnews.com/20261009000022)

**시간 경과.** 장애가 시작될 때 대기 박스는 100개다. 같은 집하 회차에 이미 확정·승인된 작업에서 시간당 440박스가 현장 공정으로 유입된다. 150분 동안 총 1,200박스가 처리 대상이 된다. 기존 이중화·수작업은 시간당 240박스를 인계한다. DAOS는 기존 처리와 겹치지 않고 독립 자원을 확보할 수 있다는 가정 아래 최초 60분에 한해 시간당 300박스를 추가 인계한다. 이후 기존 처리 속도로 돌아간다. 인계 실적은 스캔과 실제 집하 확인이 모두 끝난 박스만 센다. 공용 스캐너·이송 통로·집하장 등 병목이 확인되면 추가 처리량을 낮춰 다시 계산한다.

| 장애 경과 | 기존 대응 대기 | DAOS 적용 대기 | 양쪽에 발생한 누적 기본 운영비 |
| --- | ---: | ---: | ---: |
| 시작 | 100박스 | 100박스 | 0만원 |
| 30분 | 200박스 | 50박스 | 각 49만원 |
| 60분 | 300박스 | 0박스 | 각 98만원 |
| 90분 | 400박스 | 100박스 | 각 147만원 |
| 150분 · 집하 마감 | 600박스 | 300박스 | 각 245만원 |

기본 운영비는 구역 투입 인력 30명 × 시간당 총인건비 2만원 × 2.5시간 = 150만원, 구역 배부 임차·설비 감가 80만원, 공통 전력·시설비 15만원이다. 공통비는 장애 구간에 귀속해 총비용에 보여 주고, 두 방식의 차액에는 포함하지 않는다. 초과근무비는 복구 이후 실제 추가 유급시간으로 따로 센다. 설비 임차와 감가를 같은 자산에 중복 배부하지 않는다.

**비용 비교.** 아래 표는 장애 150분의 기본 운영비와 이후에 발생한 장애 관련 추가 비용을 합산한다. 재처리비는 추가 자재·외주 등으로 박스당 2,000원을 가정하며 별도 초과근무 인건비와 겹치지 않게 집계한다. 정규 후속 차량에 300박스의 여유가 있고, 이를 초과하면 긴급 차량 한 대(150만원)가 필요하다고 가정한다. 운임과 후속 차량 여유는 센터에서 확인할 변수다.

| 비용 항목 | 기존 대응 | 기존 대응 + DAOS |
| --- | ---: | ---: |
| 공통 기본 운영비 | 245만원 | 245만원 |
| 지연 박스 재처리비 | 120만원 | 60만원 |
| 복구 초과근무 (20 / 10인시 × 3만원) | 60만원 | 30만원 |
| 긴급 차량 (1 / 0대) | 150만원 | 0만원 |
| DAOS 비상 가동·대조 (추가 지원 9만원, 전력·소모품 3만원) | 0만원 | 12만원 |
| **사건 관련 추가비** | **330만원** | **102만원** |
| **기본 운영비를 포함한 구간 총비용** | **575만원** | **347만원** |

- **차량 한 대를 피하는 경우** 장애당 순절감은 228만원이다. 동일한 사건이 연 4회면 기존 대응의 연간 장애 추가비는 1,320만원, DAOS는 장애 추가비 408만원과 상시 운영비 600만원을 더해 1,008만원이다. 상시 운영비는 평시 유지·훈련 예산이며 표의 장애 시 추가 투입분과 구분한다. 초기비 전 연 312만원이 남고, 초기 구축비 3,000만원의 단순 회수기간은 약 9.6년이다. 구축비 3년 환산분까지 포함하면 DAOS 연간 비교 비용은 2,008만원으로 기존 대응보다 688만원 높다.
- **두 방식의 차량비가 같다면** 장애당 순절감은 78만원이다. 연 4회에서 연 312만원을 절감해 상시 운영비 600만원에 288만원 못 미친다. 차량비 절감 효과가 있는 첫 가정에서는 같은 사건이 연 8회부터 3년 회수 기준을 충족한다.
- **센터 전체 연간 비용**은 정상시 공통 운영비를 위 연간 비교 비용 양쪽에 더해 산정한다. 전 센터 인력·시설·설비·전력 등 연간 운영 원가와 이 구역의 배부 기준이 필요하다. 장애 구간의 공통비 245만원은 연간 공통 운영비에 이미 들어 있으므로 다시 더하지 않는다. 처리 지연을 실제 미회복 판매 손실로 환산할 때는 취소가 확인된 주문의 공헌이익을 적용한다. 정상적으로 나중에 인계된 주문은 실제 추가 재처리비·운임·배상만 반영한다.

현장에서는 15분 단위 대기량과 인계량, 기존 대응의 실제 전환 시각, 임차·감가 배부표, 전력 계량, 정규·추가 근무시간, 정규 차량 여유와 긴급 운임, 중앙 복구 후 적체가 해소된 시각을 수집한다. 같은 주문·마감·장애 시각으로 두 방식을 비교하고, 후속 집하가 막히면 현장 분류 완료량과 실제 인계량을 따로 보고한다.

### 대회 검증과 현장 실증

1. **포장 완료 박스의 분류 구역과 집하 회차 하나를 모의 구성한다.** 기존 이중화와 수작업 대응을 포함한 기준 절차와, 같은 절차에 DAOS를 붙인 경우에 동일한 작업과 장애를 적용한다.
2. **장애가 겹치는 조건을 시험한다.** 중앙·백업이 동시에 사용 불가한 경우, 본사와 센터 간 WAN 단절, 중앙은 살아 있는 비대칭 단절을 각각 주입한다. 공개 장애 사례의 접속 중단 길이를 참고해 150분 시나리오를 시험하되, 데모의 실행 권한 최대 60분 또는 개별 작업 승인 만료 중 먼저 도달한 시점부터 보류되는지 확인한다. 자정 전후 연결 단절을 재현해 이미 저장된 다음날 작업만 보이고 범위 밖 작업과 만료 작업은 실행되지 않는지 확인한다. 공유 구역 점유 불명·권한 만료·브로커 단절은 정지·보류로 처리되는지 확인한다.
3. **출고 가치와 안전을 함께 센다.** 추가로 집하 마감 전에 실제 인계한 건수, 복구 시 불일치와 중복, 예외 처리 시간을 기록한다. 시뮬레이션 합격 조건은 미승인 이동·이중 관제·실물 중복 작업 0건이다. 당일과 다음날 확정률, 인계 가능 물량, 취소·변경 누락을 각각 집계한다. 센터 자료와 연동 승인 확보 후 명령을 보내지 않는 관찰 모드를 거쳐 격리 구역에서 실증한다.
