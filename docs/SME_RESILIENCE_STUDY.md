## 1. 고객과 공개 근거

첫 검증 대상은 주문관리·창고관리 시스템(OMS/WMS)에서 확정 작업을 내보낼 수 있고, 중앙 서버 장애 중에도 현장 전원과 일부 장비를 사용할 수 있는 국내 중소 물류센터 1곳이다. 로봇이 없는 곳에서는 기사·창고 작업으로 범위를 좁힌다. 2024년 기준 운수업조사의 보관·창고 기업체는 2,612개였다. 이 수는 기업 규모, 자동화, 백업 여부를 가리지 않는 업종 규모이며 DAOS의 판매 대상 수는 현장 요건으로 별도 산정한다. 이 수치는 업종 전체의 자기보고다. 10인 미만 사업체는 조사 범위 밖이다. 공개 본보고서에서 국내 중소 물류기업만의 **주문 데이터 보유량, 향후 2~3일 확정 주문 비율, 주문 백업률, 독립 사본에서의 복구 성공률, 중앙 장애 손실**을 확인하지 못했다. 업종·규모 통계표는 발행처 안내에 따라 별도 요청이 필요하며, 주문의 사전 확정량과 복구 성공률은 현장에서 별도로 측정한다. 해석상 도입 기회는 이미 백업하는 기업에서도 최신 작업을 꺼내 안전하게 처리하고 그 결과를 중앙과 맞추는 데 있다.

표본 검증은 서로 다른 OMS/WMS를 쓰는 5~10개 센터의 탐색 면담으로 시작한다. 한 달간 매일 같은 시각에 다음 48·72시간 예정 물량 중 당시 확정된 건의 비율, 확정 후 취소·주소 변경률, 실제로 내려받은 작업 비율과 복구 시험 결과를 기록한다. 분모인 예정 물량은 정상 운영 후 확정된 작업 원장으로 확정하고, 교대·고객사별로 나눈다. 과거 12개월 장애표에서 원인, 업무시간 중 순중단, 마감 직전 여부, 수작업으로 이미 살린 물량, 초과근무·추가운송·배상 영수증을 모은다. 같은 원인으로 중첩된 장애는 한 건으로 묶는다. 면담 표본의 결과는 초기 고객 선택에 사용한다.

## 2. 주문 2~3일 사전 저장과 최소 구성

- **재해복구 사본**은 중앙 데이터 복원용이다. 중앙 서버와 다른 저장 장치·계정에 암호화된 사본을 두고, 기존 스토리지에서 권한 분리와 복원 시험이 가능하면 재사용한다. 정상 사본을 별도로 보존하고 침해 의심 시 자동 복제·동기화를 격리한다. [CISA StopRansomware Guide](https://www.cisa.gov/sites/default/files/2023-10/StopRansomware-Guide-508C-v3_1.pdf)
- **현장 작업 사본**은 다음 48~72시간 중 이미 확정·할당된 작업의 순환 목록이다. 정상 시 변경·취소를 포함한 증분을 5분마다 가져오고, 서명·버전·완전성 검증 후 한 번에 교체한다. 최신 사본과 변경 누락은 마지막 성공 체크포인트로 확인한다. 기사 단말에는 자기 작업만 저장하고 창고·로봇에는 필요한 작업·품목·위치 식별자만 배포한다. 사진과 영상은 별도로 산정한다.
- **실행 권한**은 별도 만료 시각을 둔다. 데모에서 정상 갱신 목표 5분, 비상 전환 시 데이터 최신성 한도 15분, 작업 쓰기 허용 최대 1시간을 우선 시험한다. 작업 승인·교대·자원 권한·비상 세션 중 가장 먼저 끝나는 시각이 실행 한도다. 15분은 전환 시점의 최신성 기준이다. 1시간은 사전에 격리·승인된 저위험 작업의 최대 창이며 유효한 승인과 안전 상태가 계속 확인되는 동안 적용한다. 단절 중 취소를 관측할 수 없는 작업은 변경 불가로 확정할 수 있는 범위에서만 처리한다. 신규 주문, 주소 변경, 유효성 불명, 예약 충돌, 재고·실물 불일치는 보류한다. 2~3일치 사본은 남은 일정의 조회와 복구에 쓸 수 있다.
- **작업 이력**은 로봇·단말 또는 현장 장비의 영속 저장소에 순번과 함께 기록한다. 앱에서는 실행 의도를 먼저 기록하고 결과 확인 후 완료를 남긴다. 장비가 동작한 뒤 기록 전에 전원이 꺼졌다면 재시작 시 실제 상태를 조회하거나 사람이 확인할 때까지 작업을 보류한다. 비상 장비에는 로컬 디스크를 쓰고, 디스크 손실·쓰기 실패·로그 용량 초과 시 새 작업을 보류한다. [SQLite WAL](https://www.sqlite.org/wal.html) · [SQLite 동기화 설정](https://sqlite.org/pragma.html#pragma_synchronous)
- **개인정보**는 배정 단위로 접근권한을 제한하고 저장·전송을 암호화한다. 작업 완료·만료 후 현장 사본 삭제 시점과 중앙 복구본의 보존 목적을 분리한다. [개인정보 보호법 제21조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0021&lsiSeq=283839&urlMode=lsScJoRltInfoR) · [개인정보의 안전성 확보조치 기준](https://www.law.go.kr/admRulSc.do?menuId=5&query=%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%9D%98+%EC%95%88%EC%A0%84%EC%84%B1+%ED%99%95%EB%B3%B4%EC%A1%B0%EC%B9%98+%EA%B8%B0%EC%A4%80&subMenuId=41&tabMenuId=183)

1일 1,000건, 주문·작업 메타데이터 건당 4KB 가정에서 전량이 미리 확정되어도 2일분은 약 8MB, 3일분은 약 12MB다. 이벤트·인덱스·사본 세대를 합쳐 10배를 잡으면 약 80MB와 120MB다. 실제 보유량은 미리 확정된 작업 수에 비례한다. 참고로 국내 리전 오브젝트 스토리지 10GB를 월 내내 보관할 때 공개 단가 28원/GB·월 기준 저장료는 280원이다(API·전송·부가세 별도). 2일과 3일의 선택은 주문 확정률과 변경률을 실측해 정한다. 인건비·연동·복구 훈련은 저장료와 따로 예산을 잡는다. ## 3. 장애 중 제어와 복구

VDA와 VDMA가 공동 개발한 **VDA 5050 v3.0.0(2026년 3월판)**은 관제와 이동 로봇 간 MQTT/JSON 통신 인터페이스다. §4.1은 로봇이 브로커 연결을 잃으면 기존 주문을 보존해 마지막으로 실행 승인된 노드까지 수행하는 동작을 정의한다. 기능 안전과 교통 제어 로직은 규격 범위 밖이다. 실제 로봇의 안전 인터록·정지 방식과 재시동 조건은 제작사 기능과 현장 위험성 평가로 검증한다. 시뮬레이션에서는 마지막 승인 노드 이전에도 안전 조건이 깨지면 정지하도록 설계한다. [VDA 5050 공식 규격 §1·§4.1](https://www.vda.de/dam/jcr%3A09f03b91-13e2-4db3-bf30-4f221710071b/VDA5050-V3.0.0-2025-03.pdf) · [ISO 3691-4:2023](https://www.iso.org/standard/83545.html)

| 상태 | 현장 동작 |
| --- | --- |
| 중앙 OMS/WMS 장애, 현장망과 기존 관제 정상 | 담당자가 비상 권한을 확인한 뒤 기존 관제를 통해 사전 승인된 단일 구역 작업만 제한 실행한다. 작업 의존성은 완료 로그로 확인한다. |
| 로봇과 브로커 단절 또는 FMS 상실 | 로봇의 자체 안전 기능을 유지한다. 이미 승인받은 구간에서 안전하게 정지할 수 있는 범위까지만 진행한다. 추가 명령과 미승인 경로 진입은 차단한다. |
| 공유 통로·엘리베이터·컨베이어 점유 불명, 센서·안전 기능 이상, 전원 장애 | 현장 안전 절차에 따라 정지 또는 보류한다. 시간 제한이 끝난 점유권만으로 재진입을 허용하지 않고 실제 비어 있음을 확인한다. |
| 보안 침해·사본 변조 의심 | 영향을 받은 장비와 사본을 격리하고 승인된 복구본을 확인한다. |
| 중앙 연결 복구 | 새 명령을 잠그고 로그·주문·실물 위치·수량을 대조한다. 미확인 작업과 구역은 격리하고, 확인된 범위부터 정상 관제권을 인계한다. |

최초 데모는 **하나의 비상 제어 노드와 분리 구역 한 곳**으로 제한한다. 양쪽이 동시에 명령하지 못하도록 정상 시 작업·구역별 단일 실행자와 세대 번호를 강제하고, 중앙 권한이 해제됐음을 확인한 범위만 비상 노드가 인수한다. 명령 수신 측은 이전 세대 명령을 거부한다. 중앙 격리와 실제 점유를 확인할 수 없으면 새 작업을 내보내지 않는다. 공유 자원의 만료는 추가 진입 권한을 막는 용도로 쓰고 현재 점유 해제는 실물 확인으로 결정한다.

복구 시 단말은 고유 `eventId`와 `sourceId/sequence`, `taskId`, 작업 버전, 관제 세대, 관측 위치를 전송한다. 중앙은 고유 키와 작업 상태 변경을 한 트랜잭션으로 기록한 뒤 커밋 성공을 확인 응답한다. 확인 응답을 잃으면 단말은 재전송하고 중앙은 같은 이벤트를 한 번만 반영한다. 별도 이벤트가 같은 작업을 완료하려 하면 작업 고유 키·버전·상태 전이로 막는다. 순번 누락, 취소 충돌, 기록과 실물 불일치는 자동 확정 대신 검토 큐로 보낸다. MQTT 관제 메시지와 별도의 복구 전송 경로를 두며, DB 중복 제거와 실물 작업 중복 방지는 각각 검증한다.

## 4. 센터 1곳 비용과 손익분기점

기존 OMS/WMS 내보내기와 단말을 사용할 수 있는 단일 센터의 **증분 계획 예산**이다. 자체 개발·설치의 가정이며 견적이나 업계 평균이 아니다. 기술 인력 1인일 41.5만원은 2026년 적용 전체 SW 기술자 공표 평균 약 41.48만원을 반올림했다. 현장 인력 시간당 총비용 1.5만원은 계산 가정이다. 2026년 법정 최저 시급은 10,320원이다. [SW 기술자 평균임금 발표](https://www.sw.or.kr/site/kipa/ex/board/View.do?bcIdx=64736&cbIdx=379&searchExt1=) · [최저임금위원회](https://www.minimumwage.go.kr/index.jsp)

| --- | ---: | ---: |

| 3년 균등 환산 연간 비용 | **118만원** | **310.7만원** |

장비·설치 예산은 재사용과 소형 현장 장비 1대를 전제로 한다. B 공수는 기존 연동을 재사용할 수 있는 단일 업무 흐름의 파일럿 가정이다. 신규 WMS, 제조사별 어댑터, 안전 설비 변경, 상시 지원, 다센터 전환은 현장 견적에 별도 반영한다. 금액은 세금·할인율을 제외했다. 비교군은 센터의 기존 절차를 유지하는 경우이며 기존 비용은 공통비로 뺀다.

**시간당 실제 회피 가능한 손실의 예시 7.5만원.** 6명이 장애 1시간당 평균 0.5시간씩 추가 유급 작업을 한다고 가정하면 4.5만원이다. 시간당 100건 중 10%에 추가 운송·지연 배상 등 3,000원의 비인건비가 발생한다고 가정하면 3만원이다. 정상 급여, 나중에 처리한 주문의 매출, 안전사고·평판 피해 가치는 제외한다. 실측 시 같은 추가 작업비를 주문당 비용에 다시 넣지 않는다. 시간당 선형화는 대회 비교용이다. 현장에서는 마감시간 전후의 비선형 손실을 실비로 다시 계산한다.

- `N`은 연간 장애 수, `H`는 수작업 처리분을 제외한 장애당 유효 중단 시간, `R`은 유효 중단 1시간당 손실이다. 기존 손실은 `N × H × R`이다.
- A는 장애당 평균 0.5시간(`a`)의 복구 시간을 절약한다고 가정한다. A 편익은 `N × min(a, H) × R`이다. 실제로는 장애별 복원 시간을 시험해 대체한다.
- B의 추가 편익은 `N × q × min(W, max(0, H − a)) × p × R`이다. `q`는 현장 전원·안전·관제권·유효 데이터 조건을 만족하는 장애 비율, `W`는 조건을 만족한 장애의 유효 비상 창, `p`는 그 창 안에서 추가로 처리해 실제 비용을 피한 물량의 비율이다. 처리율을 손실 회피율에 대입하는 것은 시간당 손실이 물량에 비례한다는 모델 가정이다. A 복구 구간과 B 작업 창은 겹치지 않게 집계한다. B의 별도 대조시간 절감은 보수적으로 0으로 둔다.
- 실제 로그에서는 장애별로 계산해 합산한다. `N`, `H`, `q`, `W`, `p`는 시장 관측치가 아니다. 2시간 창은 민감도 상단으로, 안전과 승인 유효성이 별도로 검증된 경우에만 시험한다.

| 가정 및 연간 비교 (만원) | 낮음 | 기준 | 높은 손실 |
| --- | ---: | ---: | ---: |
| 연간 장애 횟수 × 장애당 업무 중단 | 2회 × 2시간 | 6회 × 6시간 | 12회 × 12시간 |
| DAOS 가능 장애 비율 / 비상 창 / 손실 회피율 | 50% / 0.5시간 / 25% | 75% / 1시간 / 40% | 100% / 2시간 / 60% |
| 기존 절차의 장애 손실 | 30.0 | 270.0 | 1,080.0 |
| A가 절감하는 장애 손실 | 7.5 | 22.5 | 45.0 |
| B가 절감하는 장애 손실 (A 포함) | 8.4 | 36.0 | 153.0 |
| A 연간 비용 + 잔여 손실 | 140.5 | 365.5 | 1,153.0 |
| B 연간 비용 + 잔여 손실 | 332.2 | 544.7 | 1,237.7 |

**손익분기.** 기준 가정에서 기존 절차 대비 A는 연 32회, B는 연 52회부터 3년 환산 비용을 회수한다. A 대비 B는 연간 추가비 192.7만원을 부담하므로, 기준 가정의 추가 절감액 2.25만원/회에서는 연 86회가 필요하다. 높은 손실 가정의 9만원/회에서는 연 22회가 필요하다. 높은 손실 시나리오의 연 12회를 고정하면 A 대비 B의 손익분기 손실 단가는 **약 13.4만원/시간**이다. 기준 6회를 고정하면 **약 107만원/시간**이다. 기준 조건에서 B의 추가 연간 지출 한도는 13.5만원이고 높은 손실 조건에서는 108만원이다. 첫해 비용으로 판단할 때는 환산 비용 대신 258만원과 644만원을 사용한다.

따라서 현재 가정에서는 기존 절차를 유지하는 편이 세 경우 모두 총비용이 낮다. 사업의 첫 단계는 기존 백업에서 확정 주문이 실제 복원되는지 훈련하고, 누락이나 마감 손실이 큰 작업 구역만 찾는 것이다. 반복 연동을 표준화해 센터당 공수와 운영비를 줄이고, 실측 추가 회피액이 추가 비용을 넘는 고객에 한해 B를 제안한다. 자동운영의 지불의사는 기술 검증과 별도로 확인한다.

## 5. 대회 실험과 도입 판단

- **비교군**은 현행 절차(기존 수작업 포함), A(2~3일 사본 + 수동 복구), B(같은 사본 + 비상 제어·복구 로그)다. 같은 주문, 재고, 로봇 위치, 장애 시작 시각·길이와 난수 시드를 사용해 비교한다. 실제 센터 자료를 받기 전에는 1,000건/일의 합성 데이터로 시연하고, 2일·3일 보관은 각각 비교한다.
- **장애 주입**은 중앙 프로세스 종료·DB 장애, WAN 단절, FMS 종료, 로봇-브로커 단절, 중앙만 살아 있는 비대칭 네트워크, 공유 구역 점유 불명, 디스크 가득 참과 전원 재시작, 취소·주소 변경과 만료, 중복·역순·누락 이벤트, 중앙 커밋 후 확인 응답 유실, 변조 사본으로 나눈다. 15분·1시간·4시간·48시간 장애와 출고 마감 직전 조건을 포함한다. 48시간 장애에서도 비상 창이 끝나면 보류 상태를 유지하는지 본다. 정상 운영과 현장망 전체 상실도 대조한다.
- **판정 기준**은 안전 위반, 미승인 이동, 이중 관제, 실물 중복 작업, 만료 작업 실행 각각 0건이다. 기록한 완료 이벤트의 중앙 반영 또는 명시적 보류율은 100%를 목표로 한다. 정답은 중앙 DB 자체가 아니라 합성 환경의 실물·작업 원장으로 확인한다. 실패·보류도 결과에 포함한다.
- **시간과 비용**은 전환 지연, 최초 안전 작업 재개 시간, 정상 관제로 복귀하기까지의 시간, 사본에서 놓친 마지막 중앙 변경 시점, 누락 이벤트 수를 따로 기록한다. 작업 지속률 분모는 장애 기간 전체 처리 대상이며, 사전 승인 작업 내 성공률도 병기한다. 기술 목표는 적격 중앙 장애 전환 60초 이내, 정상 시 주문 복제 지연 5분 이내, 미충돌 이벤트 1,000건 대조 5분 이내로 두고 초과 건을 공개한다. 장애당 실제 회피비용은 초과근무·추가 운송·배상과 대조 시간으로 계산한다.
- **재현 및 확대**는 대표 장애 조합별 최소 30개 고정 시드로 실행한다. 사례별 성공·실패 수와 지연 중앙값·95백분위, 대조 전후 불일치 건수를 기록한다. 합성 실험을 통과하면 현장 로그로 소급 계산하고, 이후 실제 명령을 내보내지 않는 관찰 모드에서 검증한다. 실물 시험은 구역 격리와 제작사·현장 안전 담당자 확인 후 진행한다. 이 문서의 수치와 합격선은 예산·설계 가정이며 실측 성능은 별도 보고한다.
